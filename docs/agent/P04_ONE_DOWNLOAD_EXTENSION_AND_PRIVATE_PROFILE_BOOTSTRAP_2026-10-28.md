The first-party cockpit also uses browser origin-scoped localStorage key escape-hatch-profile.
- The extension reads its independent chrome.storage.local key escapeHatch.applicationAssistProfile.v1 in browser/application-assist/popup.js. Merely installing an extension does not bridge the existing locally saved user profile. A blank extension profile does not mean that the user has no profile.
- The runtime manager defaults to port 21031, while an operator-observed cockpit was on 21047. A safe startup reads authoritative installed runtime identity and its effective port rather than guessing either port or killing an unknown process.
- Open [PR #132](https://github.com/EndeavorEverlasting/EscapeHatch/pull/132) and [PR #134](https://github.com/EndeavorEverlasting/EscapeHatch/pull/134) already own applicant/developer/collaborator context isolation. It currently requires Python, which the guided installer does not establish as a consumer dependency. Do not call it a turnkey clean-machine distribution.
- Chrome officially supports Chrome Web Store distribution for ordinary users; non-Web-Store forced or normal Windows extension installation requires appropriately managed enterprise administration. Developer-mode Load unpacked requires permitted browser user action. Do not silently mutate Chrome profile files, registry, extension-install policy, startup flags or security settings to evade that boundary. Sources: https://developer.chrome.com/docs/extensions/how-to/distribute and https://support.google.com/chrome/a/answer/7649924 .

## Truthful release and telemetry contract

A private existing installation receipt, not GitHub, stores opaque owner/workspace binding, selected source commit and digest, extension package identity, actual browser extension ID, installed process instance/port and verified profile revision/hash (never field values). These states must be independent: DOWNLOADED, PACKAGE_INTEGRITY_VERIFIED, HOST_READY, OWNED_RUNTIME_HEALTHY, EXTENSION_PACKAGE_READY, CHROME_ENROLLMENT_REQUIRED, EXTENSION_INSTALLED, OWNER_BOUND, PRIVATE_PROFILE_HYDRATED, PREFERENCE_PROJECTION_VERIFIED, APPLICATION_REVIEW_READY. No completion claim solely from installer process exit 0, icon, healthy port, browser tab open, or profile source file existence.

## Falsifiable acceptance

1. Fresh Windows standard user: download a real trusted release, install and open without Git/Python/folder selection; ordinary OS/browser approval only; repeat setup idempotent.
2. Existing user: private workspace profile remains exactly the same and the extension shows correct owner-matched approved fields; no stale answer overwrite. Confirm after restart and extension upgrade.
3. Foreign active port and dirty checkout: no unexpected process kill, reset, worktree mutation, installer duplicate or data loss.
4. Wrong Chrome profile, two applicants, two developers, conflicting nonempty extension profile and absent/unknown owner: reject hydration, preserve both, no data leakage.
5. Branded 1.3.0 extension and existing app/event outcomes remain functional after installation; no required new permissions absent explicit review.
6. Exact installed extension ID, loaded version, source package digest, profile revision and real runtime endpoint are separately read back, not inferred.
