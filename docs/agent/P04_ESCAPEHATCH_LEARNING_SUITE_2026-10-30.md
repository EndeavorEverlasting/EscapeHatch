## 1. Problem, doctrine and product promise

The private retrospective establishes that an impressive document alone is not live practice, and that an incomplete personal-learning engine should not block using complementary working tools. A real interview exposed weaknesses in *operating judgment*, not simply the lack of terminology: what constitutes a representative sample, when thresholds pass, how to calibrate reviewers, how to make capacity decisions and how to address client response-time expectations. The learner needs an on-command environment for **interview rehearsal, exam preparation, independent skills development and immersive live visualization**.

The design wedge is **deterministic orchestration of learning evidence and actions**, not a claim that every interpretation of natural language is deterministic or that other visualizers lack deterministic components. A transcription model can be probabilistic; generated diagrams and coaching can be proposed by a model. Admission, typed events, diagram patch application, provenance, replay, practice rubrics, mastery state transitions, permissions, exports and error recovery must be deterministic and independently testable.

**User outcome:** Open EscapeHatch, pick an opportunity/subject/exam or resume a saved learning frontier, select a mode, start a practice or permitted live session, see the question turn into a useful diagram **as utterances finalize**, respond, receive grounded coaching, demonstrate skill, and resume later without reconstructing chats or re-entering known career facts.

**Non-negotiable:** A restricted/proctored interview or exam that forbids aids cannot be a live assistance target. Such an assessment gets pre-session practice and retrospective review only. A permitted live interview, meeting, lecture or accessibility use requires explicit relevant permission and a visible listening indicator; no stealth overlay or covert transmission. `RESTRICTED_NO_ASSIST` must fail closed.

## 4. Proposed product seams and source-verified event loop

### A. Learning session lifecycle (one session per explicit launch)

`IDLE → PREFLIGHT → READY → LISTENING_PERMITTED | PRACTICE → UTTERANCE_FINAL → VISUAL_PROPOSED → PATCH_VALIDATED → VISUAL_UPDATED → RESPONSE_PRACTICED → ASSESSED → PRIVATE_RECORD_REVIEW → COMPLETE | RESUMABLE`.

Fail-closed alternatives: `PERMISSION_REQUIRED`, `RESTRICTED_NO_ASSIST`, `AUDIO_UNAVAILABLE`, `TRANSCRIPTION_UNCERTAIN`, `MODEL_UNAVAILABLE`, `VISUAL_REJECTED`, `PAUSED`. Session state must not silently imply active listening when the source has disconnected. Provide an immediate visible Stop.

### B. Deterministic data contract (first code slice)

Synthetic `learning-session-event/v1`:
- `event_id, session_id, opportunity_ref?, course_ref?, mode, source_kind, source_revision, observed_at, finalized_at, utterance_sequence, utterance_text_ref, text_authority, transcript_confidence?, permission_receipt_ref?, event_type, payload_digest, supersedes_id?`.
- Event types: `session_started`, `utterance_finalized`, `question_detected`, `diagram_patch_proposed`, `diagram_patch_accepted`, `practice_answer_submitted`, `rubric_result_observed`, `mastery_change_proposed`, `mastery_change_consented`, `session_stopped`.
- Diagram patch: bounded node/edge operations with stable IDs; source utterance span; validator findings; safe correction path. Do not accept unsupported entities/relations as established facts; separate hypothesized model connections from transcribed wording. No fabricated graphical coordinates or hidden copy.
- Replay of duplicate/out-of-order events does not duplicate diagrams, sessions or mastery. Cross-opportunity/course/user and source-version mismatches are rejected. Transcript corrections supersede the prior meaning and cause revalidation.
- Private raw transcripts/audio off by default; local-only ephemeral capture unless specifically approved for storage. Never publish captured words or personal skill scores in tracked fixtures.

### C. Live visual experience (permitted contexts only)

Capture Windows microphone and optional system loopback through an owned/reused adapter → finalized utterance with timestamp, speaker/source and uncertainty → small, source-grounded **concept/relationship proposal** → deterministic JSON/schema validator and transactional graph patch → rendering of a diagram, flowchart, formula, process or comparison when justified. Unsupported interpretation stays a caption, not a made-up graphic. User can pin a diagram item, correct the transcript, pause, request Refine, and compare a new version to the previous one.

This is **automatic after a finalized utterance**, not a tool requiring repeated text pasting or Generate clicks. Use lightweight caption/diagram fallback when the model or network is unavailable. Explicit visual modes (Auto / Flow / Whiteboard / Formula) must remain user-controlled. Model choice, speech provider, cost, CPU and VRAM impact are measurable settings, not silent assumptions.

### D. Interview/exam/skill learning loop

Career opportunity or chosen exam objective → approved evidence-backed skills → diagnostic 3–5 questions → scenario, technical/visual explanation, worked examples → independent spoken/typed answer → deterministic scoring where objectively possible plus human/evidence review for subjective dimensions → teach-back and retest → user-approved private LatentLearning record → spaced review.

Rubric components: answer relevance in first sentence, actionable operating method, evidence/example fidelity, tradeoff/decision, clarity and time. Do not claim employer scoring from private interview records. A reviewed answer, quiz guess, source opened or skill appearing on a résumé is **not** `demonstrated`. Feed a subsequent session from the last proven frontier; schedule nothing without explicit approved scheduler activation.

### E. User-facing concepts — **design review before changing code**

**Concept A: Career-to-Study Workbench** — opportunity and skill gaps in a narrow contextual side rail, focus card for current question, diagram and evidence alongside a visible pause/stop/permission state. Favors purposeful transition from applying to practicing.

**Concept B: Immersion Studio** — full canvas, compact high-contrast caption strip, question/progress dock and optional side-by-side evidence or code sandbox. Favors live rehearsal and lecture-style learning. Separate exam-preparation and restricted-exam states.

Compare both with task completion, readability, keyboard/touch, reduced motion, screen-reader labels, contrast, responsive window size, audio gap/retry, cognitive load and low-GPU path. Preserve EscapeHatch's existing identity and visual tokens; do not add a second disconnected aesthetic or deploy mockups without operator-reviewed design selection.

## 6. Validation and falsifiable acceptance matrix

1. **Cold start:** From installed EscapeHatch, a user starts mock interview, exam study, or an unrestricted permitted live explanation with one understandable launch action. State is `READY` only when actual subsystem health passes.
2. **Live visual:** Synthetic speaker/utterance sequence becomes a caption and revised source-linked diagram automatically on finalize. Duplicate/reordered/corrected utterances remain consistent; unsupported concepts do not become asserted truth.
3. **Speech/visual latency:** Measure actual device-to-caption, finalized-caption-to-accepted-scene, dropped audio, memory/CPU/GPU and provider charges in a real consented Windows session; choose thresholds after baseline, not before measurement.
4. **Skill fidelity:** Reuse an existing approved role skill and its actual work evidence; do not substitute a global skill or create a six-skill quota; unreviewed source stays review-required.
5. **Mastery:** False positives (shown a solution, guessed answer, copied code, unverified interview answer) cannot be recorded as independently `demonstrated`; genuine verified test plus consent yields a private audit record.
6. **Permission:** Restricted proctored assessment disables live hints, capture and overlays even if an audio device is available; no cross-mode carryover. For normal permitted sessions require visible indicators and verified recording/capture consent.
7. **Resilience:** Offline / Azure denied / microphone muted / caption ambiguity / session interrupted results in honest recoverable states, not success or silent cloud fallback.
8. **Privacy:** Public synthetic fixtures contain no private speaker transcript, job profile, hidden provider source IDs, PII, private repo pointers or employer-specific claims.
9. **Regression:** Existing resume and ATS application scene contracts, P04 #69 validators, PR #145 skill scope and PR #147 progress semantics remain unaffected or pass after reviewed integration.
10. **True delivery:** Separate proof receipts for planned, schema-tested, code-tested, committed, PR-integrated, installed, actually listened, permission-observed and accepted by the user. One is not another.

Benchmark the candidate against (a) unassisted study with existing documents, (b) an existing LLM-only rehearsal tool, and (c) AudioBoarder-style transcript-to-canvas, using the **same synthetic questions**. Evaluate independent understanding/retest and recovery, not just visual polish or instant first-response confidence.
